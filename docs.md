# Development and operating constraints

Run `bun install && bun run dev`, then open <http://localhost:3000>. Use **two different browser profiles**, each with its own cookie, to join an anonymous match. **Partie erstellen** publishes an independent waiting offer without leaving the lobby. One anonymous player may create many waiting games at once and withdraw each offer separately. Other players explicitly **Beitreten** on a particular match. The first successful claim takes its only free seat; competing claims conflict. After a join, the game appears automatically as an in-app tab for both players, while the lobby remains a separate tab. Users may switch among multiple concurrent games; per-game commands are scoped to a particular authorized match ID. On reload, active game tabs are reconstructed from server-owned session memberships.

The supplied templates are 8×8 standard chess, 10×13 Choice Coins (six N/B coins per side, fixed ten pawns, edge rooks, queen and king), and 8×8 K+B+N vs K training. The board-first editor starts at 8×8. First short tap on an empty square places a white pawn, followed by knight, bishop, rook, queen, king, then an empty square. Holding a square for 500ms (or Shift+Enter) cycles the global placement mode **white → black → choice coin → white**, which stays selected for subsequent short taps on every square until the next hold. Coins have selectable option presets. Pinch adjusts ranks and files between 2 and 24, with stable rooks and expanded pawn lines; Cmd/Ctrl+arrow keys resize independently on desktop. The center icon under the board cycles random/white/black starting side. Double-click or double-tap the **invisible left or right zones below the board** to change one of sixteen board color themes or eight piece sets; desktop ←/→ keys also work. Board rotation is only Cmd/Ctrl+F, not touch or mouse rotation. Cmd/Ctrl+S or a center-down pull opens template save; Cmd/Ctrl+T (browser dependent) or a two-finger tap opens templates. Each player taps their own coins to choose pieces, then confirms **Bereit**. Browser-saved templates are local, while each match receives a validated immutable snapshot.

Press **/** or the header slash button to open the command palette. **/help** lists platform-specific shortcuts and gestures; **/draw** offers a draw or accepts an existing opponent offer. Tapping both kings in succession performs the same draw action. **/resign** and four quick taps on your own king open a confirmation modal (Enter confirms, Escape or an outside tap cancels). **/cheat Qf4** places a queen at f4 as a special experiment, overwriting only an enemy piece or empty square. Every authorized participant can use exactly one cheat **per match**, not one per player, enforced by the server. A rematch resets the allowance. All draw, resign and cheat changes are synchronised by the authoritative game service; clients do not decide results locally.

The server-side match store supports multiple independent games per anonymous browser-tab identity but is deliberately in-memory and process-local. Waiting offers expire after 90 seconds without their creator's authenticated polling heartbeat; actively polling creators may keep multiple offers open. Cleanup is enforced when a lobby, game list, or join is requested. Active games remain available in the process. **Do not deploy with multiple Next.js replicas or serverless functions expecting shared sessions.** A Redis/PostgreSQL-backed repository and distributed transactions are required before horizontal scaling. Server restart clears waiting and ongoing games. No authentication is required; random HttpOnly cookies identify anonymous players. Anonymous users can start unlimited sessions, so public deployment also needs rate limiting.

Game rules are independent of UI and transport. On a variable board castling uses an eligible home-rank king and an edge rook with a clear, safe corridor; pawns advance toward the opposing edge. Missing kings cannot be mated. Multiple kings on one side are supported and all must remain safe. Only standard chess pieces are currently represented. This app is intended to test nonstandard setups, not to reproduce standard FEN/PGN semantics on irregular boards.

Tests: `bun run test` runs domain and matchmaking **unit tests only**; `bun run check-types` runs TypeScript checking. Further validation includes `bun run lint`, `bun run knip:check`, `bun run format:check`, and `bun run build`.

## Anonymous browser-tab identity

Each tab uses a random UUID persisted in tab-local session storage and sent as an `x-chess-tab-id` header. The server combines it with a shared HttpOnly browser cookie, so Chrome Tab 1 and Chrome Tab 2 can join as different opponents even though they share cookies. Reloading a tab preserves its seat; joining from a third independent tab requires choosing one of the published waiting games. Leaving a match never deletes the browser cookie (which may still be needed by another tab). The session header is not an authentication credential by itself and cannot access matches belonging to a different browser cookie.

## Piece artwork and mobile readability

Chess pieces use scalable SVGs instead of device-dependent Unicode chess fonts on all boards and for each player's in-board Choice Coin preview. The header's **Figuren** picker switches the visual style per browser; it does not change a locked match configuration.

The default bundled **Chessnut** pieces are from [Lichess](https://github.com/lichess-org/lila/tree/master/public/piece/chessnut), with an Apache License 2.0 attribution to Alexis Luengas. The optional **Alpha** and **Companion** styles are referenced directly from Lichess' upstream GitHub repository, not redistributed here. Upstream lists Alpha as personal noncommercial use and Companion as freeware with no clear open-source redistribution grant; confirm permission with the authors before any commercial use. Chessnut is the supported offline visual style.

Game tabs within the application do not create additional anonymous browser identities. The HTTP identity is still a cookie plus browser-tab UUID; only the server decides which games that identity may access. Closing the lobby tab inside the app never resigns an active game. The existing 1.2-second polling includes the publicly available offers and every game owned or joined by the current identity, so many active games/players need a shared transactional store and more efficient transport before production scaling (issue #8).

During play, each game tab shows a top-right **Am Zug** badge when its owner is to move, including while the lobby or another game is selected. **Schach!** appears alongside it when the current player's king is checked. All attacked kings are visibly highlighted on the board, including nonstandard rectangular boards and configurations with multiple kings.

## Anonymous display names

Use the edit icon at the top right to set a name. It auto-saves in browser-local storage, is included when creating or joining a match, and is updated for all games owned by the current authenticated tab. Names are 1–32 characters with control characters disallowed. Names are display metadata only, never an authorization token.
